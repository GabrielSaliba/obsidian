## <span style="color:rgb(112, 48, 160)">Decisions</span>

- The Roadmap controls milestone scope when an old issue conflicts with it.
- M1 owns the secure foundation. M2 owns signup, login, recovery, public shell, and administrator shell work.
- RPRT-3 is a database integration parent, not one large migration task.
- M1 uses ordered immutable domain migrations.
- Clean destructive database tests run on ephemeral CI infrastructure. Shared staging receives the same reviewed migrations and is never reset by routine CI.
- M1 establishes PostgreSQL command security contracts. M3-M6 implement complete commercial behavior.
- `admin_users` owns administrator membership. `profiles.role` is not permitted.
- The first administrator is bootstrapped with a manual environment-specific SQL action and non-secret evidence.
- M1 creates unit and database test foundations. Playwright remains in its approved later milestone.
- RPRT-10 owns Storage policies and contracts only. M2 owns upload helpers and media UI.
- RPRT-41, RPRT-42, and RPRT-43 receive focused architecture grilling when each starts.
- External-service readiness uses one issue per service. Gabriel can create approved free-tier Sentry, Resend, and UptimeRobot accounts.
- Implementation and evidence are assigned to Gabriel. Explicit technical-lead approval is assigned to Guilherme.
- Only unblocked entry work enters Todo.
- Estimates use Fibonacci values from 1 through 8.
- The first forecast uses two points per engineering workday.
- RPRT-1 uses shadcn preset `b1GwReIOw`, aligned with the existing Geist font and the approved preset palette.
- The application baseline prefers the light color scheme while retaining explicit dark tokens for future opt-in behavior.
- Prettier is the repository formatting authority, with Tailwind class sorting and generated database types excluded from formatting.
- TypeScript convention enforcement explicitly rejects `any` and only the prohibited `Record<string, unknown>` form.
