## <span style="color:rgb(112, 48, 160)">Decisions</span>

- Store each unsafe verified-paid incident as one immutable `payment_recovery_cases` row and its authoritative outcome as one optional immutable `payment_recovery_resolutions` row.
- Derive the effective gate through `has_open_payment_recovery_gate(order_id)`. Do not cache a mutable gate Boolean on `orders`.
- `settlement_recovery` cases block fulfillment. `duplicate_refund` and `cancelled_order_refund` cases remain visible but do not remove an existing settlement or terminal-order truth.
- Only accepted settlement or verified full refund resolves a case. Refund request, timeout, dead letter, elapsed time, alert handling, or administrator statement cannot resolve it.
- Normal settlement and all fulfillment commands require a closed gate. Recovery settlement resolves its target case inside the same transaction and assigns the settlement pointer only when no other blocking case remains.
- Shared commands lock the order, payment attempts, recovery cases, products, and reservations in one stable relative order before append-only audit and outbox inserts.

## <span style="color:rgb(192, 0, 0)">Issues</span>

- Architecture verification found that the first draft could make `recover_late_paid_order` reject the target case that it had to resolve. The final contract now resolves the target in the same transaction and rechecks that no other blocking case remains before settlement assignment.
- Verification also found an older pointer-only fulfillment rule. It now requires both the accepted paid settlement pointer and a false recovery-gate predicate.
