## <span style="color:rgb(112, 48, 160)">Decisions</span>

- Split the administrator membership boundary into RPRT-66 so RPRT-47 and RPRT-52 could use one approved source of administrator authorization.
- Use <code>service_role</code> as the M1 worker trust boundary. The database creates lease owners and unpredictable lease tokens. RPRT-55 will protect scheduler HTTP requests later.
- Resolve the approved operation policy when a job is created and keep the full snapshot immutable for the job lifetime.
- Count only reserved provider dispatches as provider calls. Claims, lease recovery, and pre-dispatch failures do not consume a call.
- Keep provider-call results, domain transitions, operational alerts, replay authorizations, and replay consumption append-only.
- Require one unused administrator safety proof for each replay. Replay keeps the original job, business key, stable IDs, policy snapshot, request fingerprint, counters, and history.
- Keep <code>payment-session-create</code>, <code>full-refund</code>, and <code>shipping-label-create</code> non-replayable until reviewed provider evidence permits a safer contract.
- Use committed remote-session fixtures for real <code>dblink</code> races because a second session cannot see rows in the outer rollback transaction.
- Keep provider adapters, generated database types, shared staging promotion, and production changes outside RPRT-52.

## <span style="color:rgb(192, 0, 0)">Issues</span>

- The RPRT-47 and RPRT-52 dependency cycle was resolved through RPRT-66.
- PR #12 received a Vercel access failure for the commit author. It was not a database-code failure. Owner review approved the change, and the PR merged.
- Generated local skill and Supabase branch artifacts entered ESLint discovery during the final RPRT-52 gate. The fix added narrow ignores for <code>.agents/**</code>, <code>supabase/.branches/**</code>, and <code>supabase/.temp/**</code> to the fifth feature commit.
- Codex review found that JSON <code>null</code> stable IDs could pass enqueue validation and that one replay recovery test did not prove stored-state preservation. Commit <code>cc64ba3</code> fixed both findings before merge.
- Real concurrency tests depend on local <code>dblink</code> support and committed fixtures. They are not tests for shared staging or production.
