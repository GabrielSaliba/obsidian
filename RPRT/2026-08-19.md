## <span style="color:rgb(112, 48, 160)">Decisions</span>

- Use `Studio Repertório <onboarding@resend.dev>` only for explicit local and staging provider checks.
- Allow one real sandbox recipient: the email address attached to the Resend account.
- Use `delivered@resend.dev`, `bounced@resend.dev`, `complained@resend.dev`, and `suppressed@resend.dev` for controlled transport outcomes.
- Treat another real recipient as a permanent configuration failure. Reject it before provider access; do not retry a direct Resend HTTP 403.
- Keep normal unit tests network-free. RPRT-62 owns opt-in staging provider checks with unique run IDs.
- Keep open and click tracking disabled. An Auth email fails its gate if its link first uses an intermediate tracking host.
- Keep the staging Auth SMTP credential only in hosted Supabase Auth settings. Keep the application key server-only in the Vercel <code>dev</code> branch scope.
- Use separate production credentials. RPRT-67 owns the final production sender domain and senders in M7.

- Treat PR #15 as intentional mergeable partial work. It does not complete RPRT-51.
- Keep the RPRT-4 workflow files unchanged until CI integration ownership is coordinated.
- Keep shared-staging promotion and parity outside this local phase.
- Preserve exact Supabase CLI generated output instead of hand-editing RPC nullability limitations.
