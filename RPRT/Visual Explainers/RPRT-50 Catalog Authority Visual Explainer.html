Catalog authority: four tables, guarded state, public visibility

TL;DR

PR #19 makes PostgreSQL the authority for categories, products, media identity, merchandising, publication, stock, sales mode, shipping resolution, and public visibility. Ordinary catalog edits use admin RLS; stock, publication, and sales-mode transitions use narrow security-definer commands with locks, optimistic expectations, immutable audit evidence, derived admin identity, and an empty search_path.

01

Why this boundary

Before

  • Catalog rules were architecture intent, not database facts.
  • Visibility, shipping readiness, and media identity could diverge by caller.
  • Stock and publication had no serialized, audited mutation path.

After

  • Four RLS tables define the M1 catalog contract.
  • Constraints and triggers reject incomplete or unsafe states.
  • Public reads compose category, product, media, and placement gates.

Hierarchy

Decor -> Almofadas is the exact two-level tree. Capas under Almofadas is a rejected third level; parent identity cannot change later.

Slug

Sofa Lisboa converts to sofa-lisboa. Accented sofá-lisboa, double-hyphen sofa--lisboa, and duplicate sofa-lisboa forms are rejected.

B-tree identity

Unique B-tree constraints protect category (slug), product (slug), media object (bucket_id, object_path), and media slot (product_id, display_order) identities.

Media

Object identity is immutable: products/<product-id>/<random-uuid>.webp. Replace media by inserting a new row and disabling the old row, never by changing its path.

Placement

home-featured, position 0, active from Sep 1 through Sep 30 is visible only inside that window and only while its product remains public.

Shipping

Complete category package (2000, 400, 300, 200) is accepted; any partial bundle is rejected. A complete product package overrides the category bundle.

Fail closed

Removing inherited shipping from public Almofada Linho is rejected. Publication also rejects a direct product when neither product nor category supplies a complete package.

03

Admin mutation boundary

ORDINARY EDIT

Admin RLS permits approved fields: names, descriptions, SEO, ordering, active flags, package metadata, and placement windows.

GUARDED TRANSITION

Direct updates to stock, status, sales mode, media identity, IDs, and timestamps are denied.

LOCK + CHECK

Command derives auth.uid(), checks is_admin(), locks rows, and checks expected state.

AUDIT

Successful state change writes one immutable domain_transitions record.

Function safety

set_available_stock, set_product_status, and set_product_sales_mode are SECURITY DEFINER, use search_path = '', and derive administrator identity from auth.uid(); callers cannot supply actor identity.

Stock success

Expected 8, current 8, new 12: apply 8 -> 12 and audit once.

Stock conflict

Expected 8, current 10: do not overwrite. Return conflict with latest quantity 10.

Publication

A valid draft with an active category path and resolved shipping publishes successfully and receives database publication time. Missing shipping is rejected.

Sales mode

Sales-mode changes are draft-only. Changing direct_stocked to assisted atomically clears price, stock, weight, height, width, and length.
